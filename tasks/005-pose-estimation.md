# Task 005 — Pose Estimation V1

## Objective

Integrate a first markerless pose estimation stage into the processing pipeline so the system can consume extracted frames and persist structured keypoint data without coupling the rest of the application to a specific model provider.

## Context

The platform already supports video ingestion and frame extraction. The next milestone is to produce structured body landmark coordinates from the extracted frames and persist them as a primary intermediate output. This task must remain provider-agnostic at the service boundary, even when the initial implementation uses MediaPipe.

## Scope

- define a pose-estimation abstraction that can be replaced later without changing downstream logic;
- implement the initial provider using MediaPipe for landmark extraction;
- consume frames generated by the frame extraction stage;
- persist keypoint output in a structured JSON manifest;
- include frame index and timestamp in every pose result;
- capture frames without a detected pose without auto-correcting the data;
- support optional debug overlays for visual verification;
- add automated tests for interface, output format, and provider isolation.

## Out of Scope

- swing segmentation;
- biomechanical metric calculations;
- movement interpretation or recommendations;
- automatic repair or interpolation of missing keypoints;
- database-backed storage for keypoints.

## Technical Requirements

- keep the abstraction in a service/provider boundary independent from MediaPipe implementation details;
- use normalized coordinates from the estimator output when available;
- include visibility/confidence data for each keypoint when the model exposes it;
- store required keypoints: shoulders, elbows, wrists, hips, knees, and ankles;
- persist results under `sample-data/pose-estimation/<video_id>/manifest.json`;
- keep the rest of the pipeline decoupled from the concrete model implementation;
- ensure frame order remains aligned with the frame extraction timeline.

## Acceptance Criteria

- at least one sample video completes the end-to-end flow: ingestion -> frame extraction -> pose estimation;
- structured numerical keypoints are persisted for each processed frame;
- frames with no detected person are recorded instead of silently dropped;
- model/provider selection is abstracted through the interface;
- test suite, lint, and type checking remain green.

## Tests Required

- abstract interface structure is defined and enforceable;
- output schema contains the expected keypoint names and fields;
- missing pose detection is recorded as a valid result rather than an exception;
- service logic is independent from the provider implementation through mocks.

## Documentation Updates

- update `ARCHITECTURE.md` to describe provider abstraction and keypoint output expectations;
- update `IMPLEMENTATION_PLAN.md` to reflect the pose-estimation milestone status;
- add a decision entry in `DECISIONS.md` describing the provider abstraction and markerless default;
- document persistent result storage in `sample-data/README.md`.

## Dependencies

- completed video ingestion and frame extraction milestones;
- OpenCV and MediaPipe available in the project environment;
- access to at least one valid sample video for end-to-end validation.

## Definition of Done

The task is complete when pose estimation runs for a valid sample video, structured keypoints are saved and inspectable, frames without a pose are represented explicitly, and the repository stays green under automated validation.
