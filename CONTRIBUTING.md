# Contributing

## Workflow

1. Read the relevant task and specification before editing code.
2. Keep changes scoped to the task at hand.
3. Add or update tests with behavior changes.
4. Run relevant validation checks before merging.
5. Keep commits small and specific.

## Code standards

- use type hints;
- avoid speculative features;
- keep API handlers thin;
- maintain clear module boundaries;
- document important architectural decisions.

## Reporting issues

Open a task or issue with enough context for the team to understand the problem, intended behavior, and acceptance criteria.
